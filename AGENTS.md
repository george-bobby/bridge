# Bridge

Zero-dependency Node dashboard (no `npm install`) plus a Swift WKWebView shell.

- Layout (README › Layout): one-word folders `app/ bin/ data/ docs/ hooks/ legacy/ prompts/ scripts/ server/ skills/ test/`, one-word file names; keep it that way when adding files
- `bin/bridge` (was `sb`, from the project's old name slack-bridge) and every `BRIDGE_*` env var (`BRIDGE_URL`, `BRIDGE_ROLE`, `BRIDGE_TASK_ID`, `BRIDGE_REPORT`, `BRIDGE_GUARD`, `BRIDGE_DATA_DIR`, test knobs `BRIDGE_TICK_MS`, `BRIDGE_STALL_SEC`); prompts take its path as `{{BRIDGE}}`
- `npm run lint`: `node --check` on every server script, JSON parse, and fails on any non-builtin `require` (zero-dependency rule)
- CI (`.github/workflows/ci.yml`): lint + shellcheck + actionlint, `npm test` on Node 20/22/24 Linux and 22 macOS, `scripts/build.sh` on macos-15. The runner's Swift type-checker is slower than a local Mac: keep SwiftUI `body`s split into small computed views or it times out there while building fine locally
- Releases: bump `package.json` version, merge, push tag `v<version>`; `release.yml` reruns CI, checks the tag matches and creates the GitHub release
- `npm test`: policy, report parsing, end-to-end harness and workspace tests (stub agent, scratch data dir; never touches `data/`)
- After every change, apply it to the installed app before calling the task done: Swift edits (`app/`) → `npm run app`; server edits (`server/`, `prompts/`, `hooks/`, `.env`, `skills/`) → `npm restart` (skip if `npm run dev` is running and only `server/` changed; it reloads those on save)
- `npm run dev`: server in the foreground, restarting on `server/` saves (stops the launchd server first; `npm start` to go back). No watcher exists for the Swift app
- `npm restart`: pick up server edits (`server/`, `.env`). `legacy/web` is read from disk per request, so legacy UI edits need only a reload
- `npm run app`: rebuild `dist/Bridge.app` and install it to `~/Applications` (rebuild after moving the repo; its path is baked in)
- Try UI changes against scratch data: `BRIDGE_DATA_DIR=/tmp/x PORT=4400 node server`
- `LINEAR_API_KEY` lives in `.env` only; `server/env.js` deletes it from `process.env` so sessions never inherit it
- UI layers wrap app.js globals in load order: `app.js` → `harness.js` → `workspace.js`


## Native app (`app/`)

- SwiftPM + SwiftUI, macOS 15, built with the Command Line Tools: `cd app && swift build -c release`; `npm run app` packages and installs it
- `@State` is unavailable without full Xcode (its macro plugin isn't shipped): keep view state in `@StateObject private var x = Box(value)`
- Use `Text(verbatim:)` for interpolated numbers (plain `Text("\(n)")` adds locale grouping: "#35,749")
- Check the UI without screen-recording permission: `BRIDGE_SNAPSHOT_DIR=/tmp/shots app/.build/release/Bridge` writes a PNG per page
- Demo data: `npm run demo` (fictional team on :4420, fixture feeds from server/demo.js, stub agent), then run the app with `BRIDGE_PORT=4420`
- README screenshots: `BRIDGE_PORT=4420 BRIDGE_SNAPSHOT_CHAT=1732530001.000100 BRIDGE_SNAPSHOT_DIR=/tmp/shots .build/release/Bridge`, then copy into docs/screenshots (never screenshot real data)
- Styling lives in `Theme.swift` (Linear palette, StatusIcon, PriorityIcon, Chip, HoverRow); follow it rather than adding ad-hoc colors
- Motion lives there too: curves in `M` (hover, snappy, page, pop), `.hoverBox(box)` for eased hover, `Pressable`, `SlidingTabs`, `.rise(i)`, `.shimmer()`, `.floatingPanel()`; native pieces `VisualEffect` (vibrancy) and `SearchField` (NSSearchField). Use these instead of bare `onHover`/ad-hoc animations
- Sidebar order and ⌘1…⌘9 both come from `navOrder` in App.swift; the sidebar's selection pill is a `matchedGeometryEffect` shared through `\.navNS`
- Don't use SwiftUI `.inspector` in the chat: with the hidden title bar it re-adds the title-bar safe area inconsistently (expanded vs collapsed sidebar). The details panel is a plain animated trailing column
- Snapshots include a `collapsed` page (sidebar hidden) to check the traffic-light inset; `BRIDGE_SNAPSHOT_PAGES=chat,browser` limits the run to those pages, `BRIDGE_SNAPSHOT_URL=http://localhost:4420` adds a `browser` page (a browser tab in the chat)
- Keep `.scrollIndicators(.never)` on the chat transcript: with always-visible scroll bars, wrapped text near the fold makes the scroller appear/disappear forever and hangs the main thread in layout
- Sidebar groups: actions (New task, Search), Overview (Home, Inbox, Sessions), Sources (Slack, PRs, Linear), Pinned, Projects; Memory/Usage/Settings live in the footer. Settings is an in-window page (`Route.settings`, ⌘, and the footer gear; no separate Settings scene) in `Settings.swift`: sub-nav sections from `SettingsPane` (`model.settingsPane`), `SSection`/`SRow` cards (a section hides itself when search leaves it no rows, so guard rows with `Prefs.hit`), `.env` edits pooled in `EnvStore` behind one save bar, `model.envNeedsRestart` drives the restart banner. Snapshot pages `settings`, `settings-<pane>`; `BRIDGE_SNAPSHOT_SETTINGS_QUERY` snapshots a search; `usage-popover.png` is always rendered Board and list are one "Sessions" page (`model.sessionsRoute` remembers the layout; use `model.navigate(.sessions)`)
- Chat container: prev/next chat (⌥⌘↑/↓, palette; no header buttons) follows `model.chatOrder` (sidebar order). Messages: each `Transcript` owns a `MessageNav` (`Messages.swift`, held in a non-publishing `NavHolder` so scrolling never re-renders the transcript) with the floating `MessageStepper` at its top right: prompt to prompt (⌥↑/⌥↓ in the focused pane, ⌥⇧ for any message; skipped while the composer has text), scrollTo + `FlashMark` highlight, position from `scrollPosition(id:)` (`pinned` holds the last target until a hand scroll); `model.messageNavs[run]`; hovering the stepper opens `PromptList` (every prompt, click to jump; `nav.list` is a `HoverIntent`); snapshot pages `messages`, `messages-split`, `messages-list` use the long WEB-124 demo chat; tabs are Chat, Changes and browser tabs (`Browser.swift`, live `WKWebView`s kept in `model.web`); drafts and attachments are per chat in the model. Pasted images/files and big pastes become attachment chips, saved under `~/Library/Application Support/Bridge/attachments` and sent as paths in the message text
- Split panes (`Panes.swift`): the chat page is a row of `model.panes` (session + tab each); one pane looks like the plain chat (page header, tab strip, details column); side by side every pane is self-contained (`PaneHeader`: title, live badge, its own `SessionTabs(pane:)`, details toggle, ⋯, minimize to a `CollapsedPane` strip, close) and the page header keeps only the stepper and layout controls. The focused pane is the route's session and `model.chatTab`, so shortcuts act on it. No two panes show the same (session, tab); use `model.showTab` (`in:` a pane for its own strip)/`dropInPane`/`vacate` rather than setting tabs by hand. Drags (sidebar session ids, `bridge-tab:<run>\t<tab>` from tabs and pane headers) arm `DropCatcher` NSViews over each pane (drag sources must be `.onDrag` on a non-Button view: a SwiftUI `Button` swallows the drag and it never starts); ⌥-click / "Open to the Side" go through `model.openToSide`; read a pane's run with `model.runData(id)`, not `openRun`. ⌘\ split, ⌘⇧W close pane, ⌥⌘←/→ focus
- Details panel (`Details.swift`): properties (Status follows a linked Linear issue unless moved by hand; `model.linkedIssue`, `statusDisplay`), links with copy, PR activity from `GET /api/runs/:id/pr` (`changes.activity`: `gh pr view` + inline review comments, cached 45s; demo fixture in `server/demo.js` `prActivity`), the report folded with callouts. One pane: trailing column (`inspectorShown`); split: per pane (`Pane.details`, `model.toggleDetails`), a column when the pane is ≥ 800pt, else `DetailsDrawer` under it; pane runs' tasks load into `taskCache` (`model.taskData(id)`, never `openTask` in the panel). Snapshot pages `split`, `split-details`, `split-wide` (column + minimized strip), `split4`. Cost isn't shown anywhere in the app (plan usage instead); the `drop` snapshot page shows the drag highlight
- Terminal tab (`Terminal.swift`): SwiftTerm `LocalProcessTerminalView`, one per session in `model.terms`, running `GET /api/runs/:id/terminal`'s command in the login shell. SwiftTerm is pinned to 1.11.2: 1.12+ ships a Metal shader that the Command Line Tools can't compile
- Composer pieces live in `Composer.swift`: `AgentModelPicker` (agent + model + thinking in one popover), `AccessPicker`, `ContextButton` (compact), `PromptEditor` (`@` files, `#` sessions, `/` skills; keys go through a local key monitor so the text view keeps focus) and the New task `ComposeSheet`. `BRIDGE_SNAPSHOT_COMPOSER=/tmp/dir` (with a chat open) writes PNGs of the menus, popovers and the sheet
- The old web UI is kept, untouched, in `legacy/`
- The only terminal is the in-app Terminal tab: no external-terminal hand-off

## Server pieces added with the native app

- `server/projects.js`: projects (data/projects.json), session-to-project inference, per-project orchestrator ids (`orchestrator` for the default, `orchestrator-<id>` otherwise)
- `server/dotenv.js`: `.env` read/write for Settings, schema from `.env.example`; secrets are write-only
- `server/slack.js`: native Slack connector on a user token (`SLACK_USER_TOKEN`); `server/demo.js` has a fixture Slack for `npm run demo`
- `POST /api/restart` exits the server; launchd (KeepAlive) restarts it after re-rendering the skill
- `server/agents.js`: Codex/Cursor/Devin adapters into Claude's stream-json, handoff briefings, the model catalog (`codex debug models`, `cursor-agent --list-models`, `devin models list --format json`); spawn agents with `ACP_BACKEND` removed or Devin says "Not logged in"
- `server/usage.js`: plan usage (Claude oauth/usage, Codex wham/usage + session-log fallback, Cursor dashboard API); never stores or refreshes tokens. Cursor tries the cursor-agent keychain token (`cursor-access-token`/`cursor-user`) before the editor's state.vscdb (often stale) and auth files, moving on after a 401. Team/Enterprise seats get no `planUsage`: spend comes from `GetTeamSpend {teamId, searchTerm: email}` (own `spendCents` vs `effectivePerUserLimitDollars`), plus `GetMe`, `GetPlanInfo`, `GetUsageLimitStatusAndActiveGrants`. Details with `info: true` render as notes, not rows
- `server/changes.js`: per-session git status/diff/commit/push/`gh pr create`
- Claude's models and slash commands come from its stream-json `initialize` handshake (`agents.claudeProbe`, no tokens spent) plus the Anthropic models API with Claude Code's login; `/api/commands` merges that with skill folders on disk
- `jobs.clear` / `POST /api/runs/:id/clear` (orchestrators only; `/clear` in the composer too): empties the chat and drops every agent session; the app's "Clear Chat…" (⋯ menu, sidebar context menu, palette) confirms first
- `jobs.compact`: `/compact` on the resumed Claude session; other agents get a self-handoff (`run.compactBrief`, their session dropped). `/compact` typed in the composer goes there too
- `server/files.js`: `git ls-files` (or a bounded walk) for the `@` picker: `GET /api/runs/:id/files`, `GET /api/files?project=`; `GET /api/runs/:id/reference` writes a session briefing for `#`
- `server/skill.js`: every new worker (New task, Linear "Start session", `bridge spawn`, Slack pipeline, queue/relaunch) opens with the worker skill: `/fetch <linear|slack url | brief>` then Bridge's rules (worktree, report.md, asks); Codex/Cursor/Devin get SKILL.md inlined. Name from `config.harness.workerSkill` ("" = `WORKER_SKILL` in .env, default `fetch`; "none" = off); not installed → the built-in prompt. Looked up in `<repo>/.claude` then `$CLAUDE_CONFIG_DIR` or `~/.claude` (tests point `CLAUDE_CONFIG_DIR` at scratch)
- `server/watch.js`: the Slack watch (harness config `slackWatch` off|watch|triage, `slackPollSec`, `slackChannels`; state in `data/slack-watch.json`). Mentions and watched-channel posts become Inbox items (`inbox().slack`, `counts.slack` excludes triage skips); replies in threads with a chat are appended as `role: "slack"` messages with `undelivered: true`, which `jobs.startFollowup` folds into the agent's next turn. First poll only sets the watermark (the demo files its fixture once). Triage mode relays a `SLACK` turn via `harness.note`; the orchestrator answers with `bridge slack` / `bridge triage`. Bus event `slack` (`fresh`, `followups`) drives the app's notifications. Routes under `/api/slack/watch`; tests use `useConnector` with a fixture (`test/watch.test.js`)
- `bin/bridge` is the agents' tool surface, not a user CLI: `status [--since]` (decisions, to-dos, Slack items, tasks, events) replaced `catchup`/`decisions`/`show`/`todo list`; relay mode and approvals are the app's
- Every request must carry a loopback Host (DNS rebinding); non-GETs also a loopback Origin. The handler is wrapped so a throwing route answers 500 instead of crashing the server
- Snapshot page `inbox-slack` is the Inbox's Slack tab (`model.inboxTab`)
- `server/roster.js`: the orchestrator's view of every session (its project's, or all for the default one), appended to its system prompt each turn and written to `data/tasks/<orch>.sessions.md`; `GET /api/sessions`, `bridge sessions`, `bridge read <id>` (reuses `/api/runs/:id/reference`)
- `server/mcp.js`: each agent's MCP servers (`/api/mcp`, `/api/mcp/:agent[/:name[/tools|enabled|login]]`, `?run=` for a chat's worktree). Claude: ~/.claude.json + .mcp.json read directly, writes via `claude mcp add-json/remove`, status/tools/claude.ai connectors from the stream-json `mcp_status` control request, per-project on/off via `mcp_toggle`. Codex: `codex mcp list --json`, writes edit config.toml in place (`codexEdit`, keeps unmanaged keys). Cursor: ~/.cursor/mcp.json (Devin loads it too: shown as shared). Devin: `devin mcp list --json`, plugin servers off via a disabled same-name entry. Claude/Cursor "off" stashes the entry in `data/mcp-stash.json`. Status/tools for the others come from Bridge's own MCP handshake (stdio + streamable HTTP), cached by config hash (env keys sorted: Codex prints them in random order). Env/header values never leave the server; a blank value on edit keeps it. `BRIDGE_MCP_HOME` points it at a scratch home in tests. Bridge's Cursor turns pass `--approve-mcps` so enabled servers load headless
- App: `Servers.swift` (`MCPStore.shared`, Settings pane `mcp`, `model.mcpSheet` overlay for the editor and tools list, `MCPButton` in the composer), bus event `mcp`. Snapshot pages `settings-mcp`, `mcp-tools`, `mcp-add`; composer snapshot `mcp`
- Subagents/background commands: `jobs.js` folds Claude's `task_started/progress/updated/notification` and `parent_tool_use_id` events into `message.tasks` (subagent steps stay out of the parent's steps); `POST /api/runs/:id/tasks/:task/stop` sends the `stop_task` control request, `GET …/output` tails the task's output file. App: `Tasks.swift` (`TaskStrip` over the composer, `TaskCard` in the transcript, `task-<id>` tabs in `model.taskTabs`); snapshot pages `task`, `task-live`, `task-bash`, composer snapshot `tasks`; `stub:tasks` in test/stub.js
- New task workspaces: `spawnTask({ base, workspace })` (`worktree` default, `local`, or an existing worktree's path; adopted checkouts are never removed by cleanup), `GET /api/git` (`tasks.branches`). App: `Branches.swift` (`WorkspaceBar` in the sheet); composer snapshots `compose-direct`, `compose-workspace`, `compose-base`
