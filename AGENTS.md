# Bridge

Zero-dependency Node dashboard (no `npm install`) plus a Swift WKWebView shell.

- Layout (README › Development): one-word folders `app/ bin/ data/ docs/ hooks/ legacy/ prompts/ scripts/ server/ skills/ test/`, one-word file names; keep it that way when adding files
- `bin/bridge` (was `sb`, from the project's old name slack-bridge) and every `BRIDGE_*` env var (`BRIDGE_URL`, `BRIDGE_ROLE`, `BRIDGE_TASK_ID`, `BRIDGE_REPORT`, `BRIDGE_GUARD`, `BRIDGE_DATA_DIR`, `BRIDGE_LEGACY_WEB`, test knobs `BRIDGE_TICK_MS`, `BRIDGE_STALL_SEC`); prompts take its path as `{{BRIDGE}}`
- `npm run lint`: `node --check` on every server script, JSON parse, and fails on any non-builtin `require` (zero-dependency rule)
- CI (`.github/workflows/ci.yml`): lint + shellcheck + actionlint, `npm test` on Node 20/22/24 Linux and 22 macOS, `scripts/build.sh` on macos-15, then `scripts/smoke.sh` (the built app renders its main pages against the demo; a missing or blank page fails). Run it locally with `./scripts/smoke.sh app/.build/release/Bridge`. The runner's Swift type-checker is slower than a local Mac: keep SwiftUI `body`s split into small computed views or it times out there while building fine locally
- Releases: bump `package.json` version, merge, push tag `v<version>`; `release.yml` reruns CI, checks the tag matches and creates the GitHub release
- `npm test`: policy, report parsing, end-to-end harness and workspace tests (stub agent, scratch data dir; never touches `data/`)
- After every change, apply it to the installed app before calling the task done: Swift edits (`app/`) → `npm run app`; server edits (`server/`, `prompts/`, `hooks/`, `.env`, `skills/`) → `npm restart` (skip if `npm run dev` is running and only `server/` changed; it reloads those on save)
- `npm run dev`: server in the foreground, restarting on `server/` saves (stops the launchd server first; `npm start` to go back). No watcher exists for the Swift app
- `npm restart`: pick up server edits (`server/`, `.env`). `legacy/web` is served only with `BRIDGE_LEGACY_WEB=1` and read from disk per request, so legacy UI edits need only a reload
- `npm run app`: rebuild `dist/Bridge.app` and install it to `~/Applications` (rebuild after moving the repo; its path is baked in)
- Try UI changes against scratch data: `BRIDGE_DATA_DIR=/tmp/x BRIDGE_PORT=4400 node server` (`BRIDGE_PORT` only; a stray `PORT` is ignored)
- `LINEAR_API_KEY` lives in `.env` only; `server/env.js` deletes it from `process.env` so sessions never inherit it
- UI layers wrap app.js globals in load order: `app.js` → `harness.js` → `workspace.js`


## Native app (`app/`)

- SwiftPM + SwiftUI, macOS 15, built with the Command Line Tools: `cd app && swift build -c release`; `npm run app` packages and installs it
- `@State` is unavailable without full Xcode (its macro plugin isn't shipped): keep view state in `@StateObject private var x = Box(value)`
- Use `Text(verbatim:)` for interpolated numbers (plain `Text("\(n)")` adds locale grouping: "#35,749")
- Check the UI without screen-recording permission: `BRIDGE_SNAPSHOT_DIR=/tmp/shots app/.build/release/Bridge` writes a PNG per page
- Demo data: `npm run demo` (fictional team on :4420, fixture feeds from server/demo.js, stub agent), then run the app with `BRIDGE_PORT=4420`
- README screenshots: `BRIDGE_PORT=4420 BRIDGE_SNAPSHOT_CHAT=t-241125-web-124-apple-pay BRIDGE_SNAPSHOT_PAGES=home,board,inbox,linear,palette,import,chat BRIDGE_SNAPSHOT_DIR=/tmp/shots .build/release/Bridge`, then copy those seven into docs/screenshots (never screenshot real data). The README stays short: features as one-liners, the screenshots it uses and nothing else
- Styling lives in `Theme.swift` (Linear palette, StatusIcon, PriorityIcon, Chip, HoverRow); follow it rather than adding ad-hoc colors. Every `T`/`NT` color resolves per appearance (light and dark): no `Color.white`/`.black` for surfaces or text, `T.shade` for shadows and scrims, `T.rim` for floating-panel hairlines. `Appearance` (Settings › General › Theme, `model.appearance`, UserDefaults `appearance`: system|light|dark) sets `NSApp.appearance`; never `.preferredColorScheme`. `BRIDGE_APPEARANCE=light` snapshots light without saving it
- Preview deployments: `server/previews.js` turns a PR head commit's GitHub deployments, preview-host commit statuses and vercel[bot]/netlify[bot] comments into `previews: [{provider, url, state, env}]` on the pulls feed and PR activity (`test/previews.test.js`). App: `Previews.swift` (`PreviewChip`, `PreviewRows` in the details links, `model.openPreview` opens it in a browser tab of the PR's session, reusing one on that URL; no session → default browser). Snapshot page `preview`. A sidebar row must never be wider than the sidebar (it shifts the whole column): `PRMetaLine` drops the diff size via `ViewThatFits`
- Buttons follow one style guide (`// MARK: - Buttons` in Theme.swift, metrics in `B`: 28pt regular, 24pt small, 20pt mini, radius `B.radius(h)`): `LButton(.primary/.secondary/.danger/.ghost, small:, square:)` for text actions (`square` for icon-only bordered ones), `IconButton` for icon-only ghost buttons (28 in headers, 24 in rows/panes/sidebar, 20 only in dense property rows), `MoreMenu` for every "⋯" (or "+") menu, `LinkButton` for quiet links ("All", "Show 3 more"), `PickerChip` for value pickers. Never hand-roll a button's frame, radius or hover fill
- Motion lives there too: curves in `M` (hover, snappy, page, pop), `.hoverBox(box)` for eased hover, `Pressable`, `SlidingTabs`, `.rise(i)`, `.shimmer()`, `.floatingPanel()`; native pieces `VisualEffect` (vibrancy) and `SearchField` (NSSearchField). Use these instead of bare `onHover`/ad-hoc animations
- Sidebar order and ⌘1…⌘9 both come from `navOrder` in App.swift; the sidebar's selection pill is a `matchedGeometryEffect` shared through `\.navNS`
- Don't use SwiftUI `.inspector` in the chat: with the hidden title bar it re-adds the title-bar safe area inconsistently (expanded vs collapsed sidebar). The details panel is a plain animated trailing column
- Snapshots include a `collapsed` page (sidebar hidden) to check the traffic-light inset; `BRIDGE_SNAPSHOT_PAGES=chat,browser` limits the run to those pages, `BRIDGE_SNAPSHOT_URL=http://localhost:4420/api/state` (any http(s) URL) adds a `browser` page (a browser tab in the chat)
- Keep `.scrollIndicators(.never)` on the chat transcript: with always-visible scroll bars, wrapped text near the fold makes the scroller appear/disappear forever and hangs the main thread in layout
- Sidebar groups: actions (New task, Search), Overview (Home, Inbox, Sessions), Sources (`SourceKind` in Feeds.swift: Slack, GitHub, Linear, Vercel, Incidents, Granola, Datadog, Models; which show is Settings › Integrations › Sidebar sources, UserDefaults `sources.hidden`), Pinned, Projects (Default first; a project header shows only its session count and the sparkles `OrchestratorButton`; New task, Import, Memory, Archived chats, rename, move and remove are its right-click `ProjectMenu`, shared with Settings › Projects via `ProjectActions`), then a Settings row; Usage is the footer gauge. Snapshot pages `settings`, `settings-<pane>`; `BRIDGE_SNAPSHOT_SETTINGS_QUERY` snapshots a search; `usage-popover.png` is always rendered Board and list are one "Sessions" page (`model.sessionsRoute` remembers the layout; use `model.navigate(.sessions)`)

Messages: each `Transcript` owns a `MessageNav` (`Messages.swift`, held in a non-publishing `NavHolder` so scrolling never re-renders the transcript) with the floating `MessageStepper` at its top right: prompt to prompt (⌥↑/⌥↓ in the focused pane, ⌥⇧ for any message; skipped while the composer has text), scrollTo + `FlashMark` highlight, position from `scrollPosition(id:)` (`pinned` holds the last target until a hand scroll); `model.messageNavs[run]`; hovering the stepper opens `PromptList` (every prompt, click to jump; `nav.list` is a `HoverIntent`); snapshot pages `messages`, `messages-split`, `messages-list` use the long WEB-124 demo chat; tabs are Chat, Changes and browser tabs (`Browser.swift`, live `WKWebView`s kept in `model.web`); drafts and attachments are per chat in the model. Drags (sidebar session ids, `bridge-tab:<run>\t<tab>` from tabs and pane headers) arm `DropCatcher` NSViews over each pane (drag sources must be `.onDrag` on a non-Button view: a SwiftUI `Button` swallows the drag and it never starts); ⌥-click / "Open to the Side" go through `model.openToSide`; read a pane's run with `model.runData(id)`, not `openRun`. ⌘\ split, ⌘⇧W close pane, ⌥⌘←/→ focus

## Server pieces added with the native app

- `server/projects.js`: projects (data/projects.json), session-to-project inference, per-project orchestrator ids. There is no default project: **Default** (`id: "default"`, `root: true`, from `projects.withRoot()`, not in projects.json) is the root folder for sessions that match no project; its name and folder are set from the app (`POST /api/projects/default {name, path}` → data/default.json; folder falls back to `DEFAULT_DIR`, then home); it's listed first, can't be moved or removed, and owns the original `orchestrator` id; every real project gets `orchestrator-<id>`. Default's folder is the fallback everywhere (`jobs.resolveWorkdir` with no chat workdir, `meta.workdir`, `spawnTask` without a repo, the app's `contextFolder` and Memory): never the first project. A workdir is per chat (`run.opts.workdir`); there's no global one (`config.followup.workdir` is dropped). Only a Slack pipeline run with no project falls back to the pipeline repo (TARGET_REPO). `spawnTask` in a folder without `.git` runs there (`adopted: "folder"`, no worktree). Reorder indexes on the server count only real projects (`model.moveProject` converts). An orchestrator works in its project's checkout (Bridge is `--add-dir`ed); one whose session was minted elsewhere keeps that folder until `/clear`. Per-project automation (`auto`: merge, review, resolve, rebase, decide; only rebase on by default; Default's in data/default.json, a project's in projects.json, only what differs from the defaults stored): Settings › Projects › Automation (`Automation.swift`), the enabled ones rendered as a short `## This project's automation` block in the worker prompt (`jobs.automationBlock`), and `merge` lets the guard pass `gh pr merge` without `--admin` for sessions whose `BRIDGE_PROJECT` has it on (`policy.projectAuto`)
- `jobs.stop` marks the job `stopped`, so a stop you asked for ends the turn as `stopped` (not `exit 143`) and a worker goes back to pending instead of worker-gone
- Dev servers (`sources.js` `loadPorts`): `POST /api/servers/:pid/stop` stops only a pid the fresh listing returns, never Bridge's own (SIGTERM, SIGKILL after 4s); the app confirms first; app-only, so it stays out of `BRIDGE_WRITES`. App: `StopServerButton` (Home's Dev servers card, details links), `model.stopServer`; the demo only drops the row (`test/servers.test.js`)
- `server/dotenv.js`: `.env` read/write for Settings, schema from `.env.example`; secrets are write-only
- `server/slack.js`: native Slack connector on a user token (`SLACK_USER_TOKEN`); `server/demo.js` has a fixture Slack for `npm run demo`
- `POST /api/restart` exits the server; launchd (KeepAlive) restarts it after re-rendering the skill
- `server/agents.js`: Codex/Cursor/Devin adapters into Claude's stream-json, handoff briefings, the model catalog (`codex debug models`, `cursor-agent --list-models`, `devin models list --format json`); spawn agents with `ACP_BACKEND` removed or Devin says "Not logged in"
- `server/usage.js`: plan usage (Claude oauth/usage, Codex wham/usage + session-log fallback, Cursor dashboard API); never stores or refreshes tokens. Cursor tries the cursor-agent keychain token (`cursor-access-token`/`cursor-user`) before the editor's state.vscdb (often stale) and auth files, moving on after a 401. Team/Enterprise seats get no `planUsage`: spend comes from `GetTeamSpend {teamId, searchTerm: email}` (own `spendCents` vs `effectivePerUserLimitDollars`), plus `GetMe`, `GetPlanInfo`, `GetUsageLimitStatusAndActiveGrants`. Details with `info: true` render as notes, not rows
- `server/changes.js`: per-session git status/diff/commit/push/`gh pr create`
- Claude's models and slash commands come from its stream-json `initialize` handshake (`agents.claudeProbe`, no tokens spent) plus the Anthropic models API with Claude Code's login; `/api/commands` merges that with skill folders on disk
- Chats are archived, not deleted, from the app: every Archive goes through the archive dialog (`Archive.swift`, `model.confirmArchive`, `model.archiveAsk`; snapshot pages `archive-dialog`, `archive-dirty`), which asks `GET /api/runs/:id/archive` (`harness.worktreeState`: `owned` only for a worktree Bridge made) and offers "Delete the worktree" (on by default; off, with a warning, when it has uncommitted or unpushed work; absent for adopted checkouts). `POST /api/runs/:id/archive {archived, deleteWorktree, force}` (`harness.archive`, `run.archivedAt`) deletes through `cleanup` (409 `refused` on unsaved work unless `force`), closes its Inbox items and drops it from the sidebar, board, `bridge status` and the roster; Sessions › Archived (`ArchivedToggle`, `model.showArchived`, snapshot page `archived`) and the chat header bring it back. `DELETE /api/runs/:id` still exists for the API
- `jobs.clear` / `POST /api/runs/:id/clear` (orchestrators only; `/clear` in the composer too): empties the chat and drops every agent session; the app's "Clear Chat…" (⋯ menu, sidebar context menu, palette) confirms first
- `jobs.compact`: `/compact` on the resumed Claude session; other agents get a self-handoff (`run.compactBrief`, their session dropped). `/compact` typed in the composer goes there too
- `server/files.js`: `git ls-files` (or a bounded walk) for the `@` picker: `GET /api/runs/:id/files`, `GET /api/files?project=`; `GET /api/runs/:id/reference` writes a session briefing for `#`
- Common rules (`server/rules.js`, Settings › Rules, `SettingsPane.rules`, `CommonRulesSettings`, snapshot page `settings-rules`): house rules appended as `## Common rules` to every worker's and orchestrator's system prompt (`jobs.systemPrompt`, `{{USER}}`/`{{BRIDGE}}` filled). Default `prompts/rules.md` (the rules common to the gym and studio memories); an edit saves `data/rules.md`, which wins (blank = off); saving the default text or `{reset: true}` deletes it. `GET/POST /api/rules` (`{text}` or `{reset}`, 20k cap); `test/rules.test.js`
- Keep what Bridge adds to a session small (it is paid on every turn): `prompts/worker.md` is short; a report is only expected when a worker changed code (`harness.hasWork`: uncommitted changes or commits on its branch), so a Q&A turn or a follow-up on a chat that already has a report ends with no nudge; worker memory is the repo's `MEMORY.md` index (like Claude Code), not every topic file; outcomes relay to the orchestrator only for work it started (task meta `by: "orchestrator"`, set by `bin/bridge spawn`/`slack`), and an outcome that says the same as the last one relayed for that task (meta `lastRelay`, a hash of status, TL;DR, PR and asks) is not relayed again; the roster is one line per session with file paths given once as a pattern. Prompt-cache note: a resumed Claude session keeps its first system prompt, so per-turn changes there never break the cache; what costs is context size (re-read on every call), so never switch a long chat to another model for cheap turns (the new model has no cache). The chat shows the brief as plain text and no role tags (worker, follow-up, nudge)
- `server/pipeline.js`: every new worker (New task, Linear "Start session", `bridge spawn`, Slack pipeline, relaunch) opens with one message, the same for every agent: `# Task` (the brief, or its Linear/Slack link and path when long), then the pipeline (default `prompts/pipeline.md`, adapted from the /fetch skill; Settings › Pipeline, `PipelineSettings` in Pipeline.swift, snapshot page `settings-pipeline`, saves `data/pipeline.md`, which wins; blank = off: workers read their brief, Slack runs fall back to the `slack-fetch-pipeline` skill; saving the default text or `{reset: true}` deletes it), then Bridge's per-run lines (permission mode; for Slack runs the toggles, emit.sh and the closing JSON verdict). `{{URL}}`, `{{BRIEF}}`, `{{USER}}`, `{{BRIDGE}}` are filled in. First turn only, never the system prompt. `GET/POST /api/pipeline` (`{text}` or `{reset}`, 40k cap); `test/pipeline.test.js`
- `server/watch.js`: the Slack watch (harness config `slackWatch` off|watch|triage, `slackPollSec`, `slackChannels`; state in `data/slack-watch.json`). Mentions and watched-channel posts become Inbox items (`inbox().slack`, `counts.slack` excludes triage skips); replies in threads with a chat are appended as `role: "slack"` messages with `undelivered: true`, which `jobs.startFollowup` folds into the agent's next turn. First poll only sets the watermark (the demo files its fixture once). Triage mode relays a `SLACK` turn via `harness.note`; the orchestrator answers with `bridge slack` / `bridge triage`. Bus event `slack` (`fresh`, `followups`) drives the app's notifications. Routes under `/api/slack/watch`; tests use `useConnector` with a fixture (`test/watch.test.js`)
- `bin/bridge` is the agents' tool surface, not a user CLI: `status [--since]` (decisions, to-dos, Slack items, tasks, events) replaced `catchup`/`decisions`/`show`/`todo list`; relay mode and approvals are the app's
- Streaming: the app never re-fetches a transcript per token. `delta` events carry a global `seq` (`jobs.flushLive`); `GET /api/runs/:id` flushes the live message first and answers `{run, seq}` (serialised body cached by the file's stamp); the app patches its copy with `Delta.apply` (Core.swift) and replays logged deltas newer than a snapshot's `seq`. A new delta field must be handled there too, or that delta falls back to a re-fetch (`test/harness.test.js` checks snapshot + replay equals the saved run). Run summaries, costs, usage and search come from per-file caches in `store.js` keyed by inode/size/mtime (`test/cache.test.js`): never parse every run file on a hot path
- Every request must carry a loopback Host (DNS rebinding), and a loopback Origin or same-origin/none `Sec-Fetch-Site` when it sends one (checked once at the top of `handle()`, not per route). Sessions can reach the API too, so the guard (`policy.js` `BRIDGE_WRITES`) denies a session's writes to it except the routes `bin/bridge` and `scripts/emit.sh` post to: a new `bin/bridge` write route must be added there. The handler is wrapped so a throwing route answers 500 instead of crashing the server
